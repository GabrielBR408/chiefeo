## [Unreleased]

### Added

- **Unified auth layer — Phase 1 (optional accounts + referral tracking).** A shared, opt-in account layer for every chiefeotool.com tool, launching *optional* — existing users keep un-gated free access, new users can sign up to get a referral link, and **no paywall is enforced**. All tools already share the one Supabase project, so accounts + the referral graph live in one place. Nothing here is applied to the live database or Supabase settings yet — it's staged for review (see `auth/README.md`).
  - **`migrations/004-auth-profiles-referrals.sql`** — new `public.profiles` table (one row per `auth.users`, keyed on `user_id`): `referral_code` (unique, auto-generated), `referred_by` (nullable self-FK), `referral_count` (confirmed referrals), `free_until` (reward window), soft-delete `deleted_at`. Referral logic lives entirely in database triggers so it can't be raced or faked from the client: `handle_new_user` creates the profile and resolves `referred_by` from signup metadata (blocking self-referral); `handle_email_confirmed` + idempotent `credit_referral` count a referral only once the referred account **verifies its email**, and unlock `free_until = now() + 365 days` the first time a referrer reaches **3** confirmed referrals (threshold + reward are labelled constants). RLS lets a user read only their own row; a guard trigger blocks the client from editing referral/reward columns. Idempotent; backfills a code for existing accounts. (Numbered 004 — 003 is the already-applied-in-prod `003-task-type.sql`.)
  - **`api/referral.js`** — read-only Vercel serverless endpoint. `GET /api/referral` returns the caller's referral status (`referralCode`, `referralLink`, `referralCount`, `freeUntil`, `unlocked`, `threshold`) via Supabase `Bearer` token or the same `x-api-key` mapping as `intake.js`/`score-task.js`; `GET /api/referral?validate=CODE` (no auth) checks a `?ref=` code before signup. Reuses the existing `SUPABASE_URL` / `SUPABASE_SERVICE_KEY` env vars.
  - **`auth/optional-access.js`** — framework-agnostic client wrapper shared by all tools: `getAuthState()` → `{ isLoggedIn, user, referralCode }` (never blocks), `captureReferralFromUrl()` (stashes `?ref=`), SDK-native `signUpWithReferral` / `signIn` / `signOut` (the "auth routes" in a static+serverless stack), and a vanilla `mountAnonBanner()`.
  - **`auth/react-optional-access.js`** — React binding (`useOptionalAccess()` hook + `<AccountBanner/>`), written with `React.createElement` so it needs no build step and works with the CDN React this repo already loads.
  - **`auth/callback.html`** — shared static page that finalizes email-confirmation and OAuth redirects, then bounces back to the app.
  - **`auth/README.md`** — integration guide, Supabase settings checklist, end-to-end flow, and the deliberate "flip the switch" plan for later moving tools behind a hard login. The ChiefEO task app's existing login gate is **unchanged** — this work is purely additive.
- **Task Types feature (Advanced Mode).** Categorize each task as one of `action` (default), `quick_fu`, `track`, `office_only`, or `delay`. Auto-detected server-side from subject keywords during scoring (`/api/score-task` now returns `task_type` alongside priority info), manually overridable per-task via a dropdown in the EditForm panel. When the Advanced Mode toggle in Settings is on: a chip strip appears above the active task list (All / Action / + every enabled type) with a per-chip eye icon for hide-from-view, an amber "X type(s) hidden — Show all" banner, and a small color-coded type badge inline next to the due-date label on each task card. Per-chip hide is per-account in `localStorage` so "I'm WFH today, hide Office Only" survives reloads on this device but doesn't sync across devices. An explicit chip pick of a hidden type still shows it (override). Settings → Priorities gains an **Advanced Mode** card at the top with the toggle and (when on) a keyword editor: one group per type in evaluation order, each with a type-level switch (omit whole type), tap-to-disable individual keywords, × to delete (default or custom), and inline "+ keyword" input with duplicate-add guard. Default Advanced Mode is OFF — existing users see no UI change. Migration `003-task-type.sql` (`task_type TEXT NOT NULL DEFAULT 'action'` column + CHECK constraint enforcing the vocabulary + index) was applied to production Supabase on 2026-05-01.
- **Auto-generated metadata indicators for due dates and priorities.** New `tasks.due_date_auto` and `tasks.priority_auto` BOOLEAN columns (migration `002-due-date-priority-auto-flags.sql`, default FALSE so legacy rows render without the indicator) track whether each value was filled in by the system or typed by the user. `api/intake.js` flags both TRUE on insert (intake-imported tasks are scored by the Gmail keyword/sender/due-date heuristics, never by the user). The web app's Quick-Add modal flags both FALSE — the user picked the tier and (optionally) typed the due date themselves. Editing a flagged date or moving the priority dot in `EditForm` clears the corresponding flag. `TaskCard` renders a small lightning-bolt corner mark on the priority badge when `priorityAuto`, and an "AUTO" pill next to the due-date label when `dueDateAuto`. `EditForm` shows the AUTO pill next to the Due Date and Priority section labels. Tapping any indicator shows a toast hint ("Auto-generated — tap edit to override with manual values"). Migration is idempotent.
- **`migrations/` directory** with a tracked SQL home for schema changes. First file `001-completed-at-trashed-at.sql` is the same idempotent (`IF NOT EXISTS` + `IS NULL`-guarded) version of the `completed_at` / `trashed_at` migration that has now been applied in production (2026-04-25). Future schema changes get a numbered file here instead of only living in CHANGELOG prose; `migrations/README.md` documents the manual apply-via-Supabase-SQL-editor flow.
- **Phase 6 trash auto-expire is now live in production.** The `AUTO_DELETE_TRASH_ENABLED` env var is set to `"true"` in the Vercel Production environment, so `api/cron-expire-trash.js` no longer short-circuits. The cron runs nightly at 03:00 UTC and permanently deletes any `tasks` row with `trashed=true` AND `trashed_at < now() - 30 days`. First-run blast radius was verified to be 0 rows before the flag was flipped.
- **Optional `tierMappings` field** in the priorities config JSONB blob, e.g. `{ "tierMappings": { "High": { "start": 5.5, "peak": 8.5 }, "Medium": { "start": 3.0, "peak": 5.5 }, "Low": { "start": 1.0, "peak": 3.0 }, "Suppress": { "start": 0.0, "peak": 1.0 } } }`. When present, `/api/score-task` uses the user's bands; when absent, it falls back to the server-side defaults baked into the function. No migration is needed — the field is optional and existing rows without it keep behaving identically.
- **`POST /api/score-task`** — new Vercel serverless function that owns the proprietary scoring IP (the default keyword library, sender→tier lookup, keyword/sender tier combination, and due-date defaults). Accepts `{ name, senderEmail, receivedDateISO, explicitDueDate, todayISO, tierOverride? }` and returns `{ tier, startPriority, peakPriority, dueDate, matchedKeywords }` — the keyword library itself is never returned. Authenticates via either a Supabase `Authorization: Bearer <access_token>` header (the browser flow) or the same `x-api-key` → `CHIEFEO_USER_ID_<LABEL>` mapping that `api/intake.js` uses (the Claude skill flow). Reads the user's priorities config (custom people, custom keywords) via the SERVICE ROLE key and falls back to server-side defaults when fields are missing. The browser now calls this endpoint from `handleQuickAdd`, `rescoreAllTasks`, and a 250ms-debounced effect inside `QuickAddModal` instead of running the scoring functions locally.
- **Trash auto-expire cron** at `api/cron-expire-trash.js`, scheduled via `vercel.json` for `0 3 * * *` (03:00 UTC daily). Feature-flagged off by default: every run returns `{ skipped: true, reason: "feature_flag_off" }` unless the Vercel env var `AUTO_DELETE_TRASH_ENABLED` is the literal string `"true"`. When enabled, deletes every row in `tasks` with `trashed=true` and `trashed_at` older than 30 days, using the Supabase SERVICE ROLE key to bypass RLS, and returns the deleted count parsed from PostgREST's `Content-Range` header. Stays off until Phase 6 ships.
- **Cleanup** card on the Priorities/settings page lets the user permanently delete completed tasks older than a chosen window (30 days, 90 days, 6 months, 1 year). Counts matches against the locally loaded task list, opens a confirmation modal showing the count, and on confirm runs a single Supabase `DELETE` filtered by `user_id + complete=true + completed_at < cutoff`. Tasks with NULL `completed_at` (completions from before Phase 3) are excluded — only tasks whose completion time is known get swept. Shows a "Deleted N completed tasks." toast on success.
- `tasks.completed_at` and `tasks.trashed_at` (TIMESTAMPTZ) columns are now read and written by the frontend. The central `updateTask` mutator pairs every `complete`/`trashed` flag flip with its corresponding timestamp (or NULL on un-flip), and `dbRowToTask` / `taskToDbRow` / `dbUpdateTask` map the new fields. Pre-existing rows with NULL timestamps are tolerated (they fall through every "older than X" sweep).
  > **Migration required.** Run in the Supabase SQL editor before merging:
  > ```sql
  > ALTER TABLE tasks ADD COLUMN completed_at TIMESTAMPTZ;
  > ALTER TABLE tasks ADD COLUMN trashed_at   TIMESTAMPTZ;
  > UPDATE tasks SET completed_at = updated_at WHERE complete = true AND completed_at IS NULL;
  > UPDATE tasks SET trashed_at   = updated_at WHERE trashed  = true AND trashed_at   IS NULL;
  > ```

### Changed
- **Edit screen buttons clarified — Save split from Mark Complete.** The bottom green "Done" button on the edit panel was ambiguous: users read "Done editing" but it actually marked the task complete. The completion intent is now its own highlighted green "Mark as Complete" checkbox at the top of the edit form, independent of the auto-save edit fields below — it commits only when the user taps Save Changes, so saving edits never marks a task complete by accident. The bottom button is renamed to "Save Changes" and recolored blue (`#3b82f6`) to match the brand. Three save branches: marks complete + slide-out animation (if box checked & task not already complete), reopens (if box unchecked & task currently complete), or just closes the panel (if no completion-state change). The Mark-as-Complete row initializes from `task.complete` so editing a completed task pre-checks the box, and the Trash link below stays put.
- **Blue gradient color system replaces the red→amber→indigo priority palette.** `TIER_COLOR` is now four shades pulled from the staircase logo: dark blue (`#2B5F8A`) for High, medium blue (`#4A8DB8`) for Medium, light blue (`#7CB4D4`) for Low, neutral gray-blue for Suppress. Same chip pattern (tinted bg + darker fg + border), shifted to a single hue family so higher priority reads as deeper / more saturated rather than as a different color. `PriorityGraph` band fills, Y-axis labels, score badges, card left stripes, tier pickers, keyword chips, and due-date defaults grid all auto-pick up the new palette. Summary cards: **Overdue stays red** (urgency, not priority — different axis, kept on purpose). Due Today shifts to medium blue, This Week to light blue. Active-border + filter-status text colors track.
- **Staircase logo in the in-app header, splash, and AuthScreen.** Replaces the inline 3-horizontal-bars SVG with a staircase: three blue bars (light → medium → dark, left to right) with a white stair-step line tracing the upper-left edges. Bumps `S.titleIcon` from 24×24 to 30×30. The PWA icons under `/icons/` (favicon, apple-touch-icon, install icon) still ship the prior 3-bar design and are out of scope here — they need a regenerated PNG set, not an inline SVG swap. Tracked as a follow-up.
- **Brand refresh: new icon, splash screen, header polish, meta tags.**
  - Replaced the Phase 2 placeholder "CE" wordmark icon with a new flat icon: a blue (#3b82f6 → #2563eb) rounded square containing three descending white bars representing an auto-prioritized list. Source SVG lives at `icons/icon.svg` (plus `icons/icon-dark.svg` and `icons/icon-light.svg` variants for dark/light contexts).   - Added a branded boot splash that covers the page until React mounts: dark navy gradient (`#0f172a → #1e293b`) with a centered 88px app icon, "ChiefEO™" wordmark in a white→light-blue gradient, and a small spinner. ### Security
- Added Subresource Integrity (`integrity` + `crossorigin="anonymous"`) to all CDN-loaded `<script src>` tags (React 18.2.0, ReactDOM 18.2.0, Babel Standalone 7.23.9). Hashes are sha384 and were computed from the official npm tarballs that cdnjs mirrors, so a tampered or substituted CDN payload will be rejected by the browser. Note: the Supabase ESM bundle is loaded via a JavaScript `import` statement (not a `<script src>` tag), where SRI is not currently expressible via attribute and is therefore tracked as a separate concern.
